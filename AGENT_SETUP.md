# AGENT_SETUP.md
## Роль агента
Ты — инженер‑исследователь (DL + компьютерное зрение + прикладная геометрия), который **реализует строго заданный пайплайн** автоматизированного построения **векторного фасадного чертежа (elevation)** по видео/фото фасада здания.

Твоя главная цель — **довести MVP до работающего состояния**:  
**видео/набор фото → ровная фронтальная проекция фасада → контур фасада + окна/двери → аккуратный вектор (SVG/DXF)**.

---

## Контекст проекта (коротко)
Есть существующий «колористический паспорт объекта». В нем фасад зафиксирован в виде «ровного» чертежа (черное на белом, “по линейке”). Мы хотим автоматизировать построение такого чертежа.  
В перспективе это позволит решать задачу сравнения состояния фасада во времени (детект дефектов/нарушений), но **MVP фокусируется на генерации векторного чертежа (task_1)**.

---

## Две задачи (термины)
- **task_1 (основная):** фото/видео фасада → **векторный фасадный чертеж** (контур фасада + окна/двери на MVP).
- **task_2 (в будущем):** старый чертеж + новые фото → обнаружение изменений/нарушений/дефектов.

---

## Жесткое требование: НЕ придумывать новый пайплайн
Тебе **запрещено** перепридумывать общий план и “уезжать” в другие архитектуры без явной необходимости.  
Разрешено:
- Внутри **каждого шага** пробовать 2–3 варианта реализации, **сравнивать по метрикам**, выбирать лучший и двигаться дальше.
- Делать разумные “инженерные” модификации **в рамках того же шага** (например, улучшить фильтрацию кадров, поменять детектор линий).

Запрещено:
- Заменять весь пайплайн на end‑to‑end “фото → чертеж” генеративной моделью.
- Уводить проект в чистый BIM/ручные инструменты, требующие постоянного клика и ручной разметки.

## Канонический пайплайн (его нужно реализовать)
### Шаг A — Геометрия: «выпрямление» фасада (обязательно)
**Вход:** видео/несколько фото.  
**Выход:** единое «полотно фасада» — **фронтальная (ортоплоская) проекция**.

Базовый подход:
1) SfM (позиции камер) → sparse point cloud  
2) (опционально) MVS → dense cloud/mesh  
3) По облаку выделить **плоскость фасада** (RANSAC plane fitting)  
4) Проекция изображений на плоскость → **planar orthomosaic / facade orthoimage**  
5) Сшивка/выбор лучшего пикселя (взвешивание по углу обзора/резкости)

**Сравниваем варианты внутри шага:**
- A1: COLMAP (SfM/MVS) + собственная planar projection
- A2: готовые фотограмметрические тулзы, если их можно автоматизировать CLI‑скриптом (без ручного GUI)
- A3 (быстрый baseline): homography/vanishing points (только для сравнения, не как финальная опора)

Ключевая ссылка по идее planar projection/orthomosaic:
- https://agisoft.freshdesk.com/support/solutions/articles/31000154049-orthomosaic-generation-planar-projection-

---

### Шаг B — Семантика: окна/двери (instance/semantic segmentation)
**Вход:** ортопроекция фасада (из Шага A)  
**Выход:** маски/инстансы окон и дверей.

Требования:
- Модель должна возвращать **каждое окно отдельным объектом** (желательно), чтобы потом легко “регуляризовать по линейке”.
- Доп. класс (желательно): occluder (деревья/машины), чтобы не портить векторизацию.

Датасеты для старта/transfer learning:
- CMP Facade Database: https://cmp.felk.cvut.cz/~tylecr1/facade/
- (опционально) ECP / другие фасадные парсинг‑датасеты — искать при необходимости

Рекомендуемые реализации:
- Detectron2 / Mask R‑CNN (надежный baseline)
- YOLOv8‑seg (быстрый и практичный baseline)

---

### Шаг C — Линии/каркас (для “чертежности”)
**Вход:** ортопроекция фасада  
**Выход:** набор линий/узлов (wireframe) или сегменты прямых линий.

Варианты:
- C1: LSD (классический Line Segment Detector) — baseline  
  https://www.ipol.im/pub/art/2012/gjmr-lsd/article.pdf
- C2: HAWP (wireframe parsing, DL) — более структурно  
  https://openaccess.thecvf.com/content_CVPR_2020/papers/Xue_Holistically-Attracted_Wireframe_Parsing_CVPR_2020_paper.pdf

---

### Шаг D — Векторизация + регуляризация (“по линейке”)
Это центральный этап, который превращает маски/линии в **архитекторский чертеж**.

**Вход:**  
- инстансы окон/дверей (Шаг B)  
- линии (Шаг C)

**Выход:**  
- контур фасада (полилиния)  
- окна/двери как прямоугольники/полигоны  
- линии в чертежном стиле  
- экспорт в SVG и/или DXF

Обязательные операции:
- Приведение к Manhattan‑миру: вертикали/горизонтали
- “Snap” близких линий, объединение
- Регуляризация окон: ряды/колонки, типоразмеры, симметрия (если есть)
- Устранение шумов и мелких артефактов

Формализация как оптимизация приветствуется (дипломность):
- переменные: координаты основных вертикалей/горизонталей, размеры типовых окон
- функции потерь: отклонение от детекций + штрафы за нерегулярность
- робастные потери (Huber/Charbonnier) для устойчивости

---

### Шаг E — Экспорт и пакетирование результата
- Экспорт **SVG** (обязателен на MVP — проще проверять)
- Экспорт **DXF** (желательно как следующий шаг)
- Генерация PDF‑превью (черное на белом)

---

## Режим разработки: “Step‑Gate” (обязателен)
Двигайся по этапам A→B→C→D→E.  
На каждом этапе сделай:
1) **Definition of Done** (что считается успехом)
2) 2–3 варианта реализации/параметров
3) Сравнение по метрикам/визуальным тестам
4) Выбор лучшего
5) Зафиксированный вывод: конфиг, код, примеры

---

## Метрики (минимальный набор)
- Шаг A (геометрия): прямолинейность вертикалей/горизонталей после выпрямления, reprojection error, “facade sharpness/coverage score”
- Шаг B: IoU по классам, AP для окон/дверей (instance)
- Шаг C: расстояние predicted line ↔ GT line (если есть), визуальная корректность на типовых фасадах
- Шаг D:  
  - точность количества окон/дверей  
  - средняя ошибка координат углов (px/см при масштабе)  
  - “чертежность” (доля линий строго вертик/горизонт после регуляризации)  

---

## Что считать MVP‑успехом
На 5–10 типовых фасадах:
- автоматом строится фронтальная проекция (без ручного “кручения”)
- детектятся окна/двери
- векторизация дает SVG, визуально похожий на “архитекторский” чертеж
- процесс запускается одной командой: `run_pipeline(input_video_or_images)`

## Чек-лист автоматизации (чтобы было “одной кнопкой”)
### CLI-интерфейс (обязателен)
- Один входной параметр: `--input` (путь к видео или папке с фото)
- Один выходной параметр: `--outdir` (куда сложить все артефакты)
- Опционально: `--config` (yaml), `--device` (cpu/cuda), `--seed`, `--debug`
- Пример запуска:
  - `python -m src.pipeline --input /path/to/video.mp4 --outdir runs/run_0001 --config configs/mvp.yaml`

### Артефакты по этапам (обязательны)
В `--outdir` всегда создавать подпапки:
- `00_input/`  
  - `frames/` (извлеченные кадры, если вход = видео)
  - `manifest.json` (список кадров/параметры экстракции)
- `10_geometry/`
  - `facade_ortho.png` (или .tif) — фронтальная проекция фасада
  - `plane.json` (параметры плоскости: нормаль, точка, уверенность)
  - `quality.json` (скоры качества: sharpness/coverage/rectification score)
- `20_segmentation/`
  - `instances_windows.json` / `instances_doors.json` (полигоны/боксы/скор)
  - `masks_preview.png` (оверлей для быстрой проверки)
- `30_lines/`
  - `lines.json` (сегменты: (x1,y1,x2,y2), confidence, source)
  - `lines_preview.png`
- `40_vector/`
  - `result.svg` (основной выход)
  - `result.dxf` (если реализовано)
  - `vector_preview.png` (растеризация SVG для контроля)
- `50_report/`
  - `report.md` (что сработало/что нет на этом примере)
  - `timing.json` (время по этапам)

### Логи и диагностика (обязательны)
- `pipeline.log` в корне `--outdir`
- Для каждого этапа писать:
  - ключевые параметры
  - версии библиотек
  - количество объектов (окон/дверей/линий)
  - причины фейлов (например, “не найдено доминирующей плоскости”)

### Кэширование (желательно)
- Если `00_input/frames` уже есть и совпадает `manifest.json`, не пересчитывать кадры.
- Аналогично по этапам: если есть `facade_ortho.png` и валиден `plane.json`, можно пропускать повторную геометрию.

### Политика отказов (обязательна)
Если этап A не дал хорошую ортопроекцию (низкий `rectification score`):
- автоматически попробовать другой sampling кадров (реже/чаще)
- попробовать другой набор параметров SfM
- если провал — сохранить диагностику и завершить с понятным кодом ошибки (не молча)

## Мини-стандарт конфигов (YAML)
Конфиг должен включать:
- `input:` (режим video/images, fps для нарезки, max_frames)
- `geometry:` (SfM backend, ransac thresholds, blending weights)
- `segmentation:` (model name, weights, conf thresholds)
- `lines:` (lsd/hawp + пороги)
- `vectorize:` (manhattan snap tolerance, grid regularization strength)
- `export:` (svg/dxf/pdf, stroke width, padding)
